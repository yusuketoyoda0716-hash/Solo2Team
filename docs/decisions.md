# 設計判断の記録

設計上の判断とその理由を、1〜3行で残す。

## フェーズ0：環境構築

- **Linter は oxlint を使う**：Vite の公式テンプレート（react-ts）が採用しているため、そのまま使う。高速で設定ファイルが1つで済み、React Hooks のルールなど必要なチェックはそろっている。
- **フォーマッタは Prettier を使う**：書式の判断を人がしなくて済むようにする。oxlint のデフォルトは書式を扱わないので、役割がぶつからない。
- **フォルダは機能ごと（`src/features/*`）に分ける**：ボード、タスク、メンバーなどの機能単位でコードがまとまり、フェーズごとに機能を足していっても既存の構成を崩さずに済む。共通のUIは `components/`、型は `types/` に分ける。

## フェーズ1：ソロで完結するカンバン

- **子が親の ID を持つ（`Board.workspaceId`、`Column.boardId`、`Task.columnId`）**：フェーズ4で DB に移すとき、外部キーとしてそのまま対応させられる。親が子の ID 配列を持つ形と違い、同じ情報を二重に持たないので食い違いが起きない。
- **並び順は `position: number` で持つ**：配列の順番に頼らず、どの単位（ワークスペース内・ボード内・列内）での順番かを各データ自身が持つ。
- **日時は ISO 8601 文字列で持つ**：`Date` 型は JSON にするとき文字列になり、読み戻しても `Date` に戻らない。最初から文字列にしておけば、localStorage への保存と読み込みで型がずれない。
- **Workspace に「個人用／チーム用」の区別を持たせない**：個人用は「メンバーが1人のワークスペース」として扱う。チーム機能を足しても型を作り直さずに済む。
- **状態管理は `useReducer` + Context（`src/lib/kanban/`）**：まだ外部ライブラリが要る規模ではないので React 標準で作る。データの持ち方と操作を `lib/` の1か所にまとめ、フェーズ4で DB に移すときもここを差し替えれば済むようにする。
- **reducer は純粋関数にし、ID と時刻は action を作る側で決める**：同じ入力なら必ず同じ結果になるので、動作を確かめやすい。存在しない ID への操作は何もしない。
- **データは ID をキーにしたオブジェクトで持つ**：ID での検索・更新・削除が直接できる。画面に並べるときは selector で `position` 順に並べ替える。
- **削除は子までまとめて消す**：ボードを消すとその列とタスクも、列を消すとそのタスクも消える。親のいないデータが残らないようにする。
- **state 用と dispatch 用で Context を分ける**：操作しかしないコンポーネントが、データの変更のたびに再描画されないようにする。
- **開いているボードは `App` の `useState` で持つ**：保存するデータではなく画面の状態なので、reducer には入れない。未選択や削除済みのときは描画のたびに先頭のボードを選び直すので、`useEffect` で状態を合わせる必要がない。
- **入力欄＋ボタンを共通部品 `TextInputForm` にする**：ボード・列・タスクの追加と名前変更で同じ形が繰り返されるため。空白だけの入力を送らない処理を1か所にまとめられる。
- **スタイルは CSS Modules**：Vite だけで使え、クラス名がファイルの外とぶつからない。色は `index.css` の CSS 変数にまとめ、ダークモードにも対応させる。
- **タスクの追加はタイトルだけ、説明は編集で入れる**：思いついたことをすぐ書き留められるよう、追加の手間を最小にする。編集はモーダルを使わず、カードがその場で入力欄に切り替わる形にし、どのタスクを触っているかが見失われないようにする。
- **保存データは `{ version, state }` の形で localStorage に置く**：データの形を変えたとき、古い形式を見分けて変換できるようにする。
- **読み込んだデータは `unknown` として受け取り、形を確かめてから使う**：localStorage は外から書き換えられるので、型の上だけで信用しない。形が壊れているときは初期状態で始め、元のデータは別のキー（`solo2team:kanban:corrupt`）に退避して、上書きで失わないようにする。
- **localStorage が使えなくてもアプリは止めない**：シークレットモードなどで読み書きが失敗しても警告だけ出し、その回はメモリ上で動かす。

## フェーズ2：操作性

- **ドラッグ＆ドロップは `@dnd-kit/core` + `@dnd-kit/sortable`**：安定版で情報が多く、キーボード操作と読み上げにも対応している。新しい `@dnd-kit/react` はまだ 0.x で API が変わる可能性があるため見送った。
- **移動は `task/moved`（移動先の列と何番目か）で表し、影響する列の `position` を 0 から振り直す**：番号の重なりや飛びが起きず、並びが常に一意に決まる。1列のタスク数は多くないので、振り直しの手間は問題にならない。
- **ドラッグ中の並びは画面側のプレビューで持ち、置いたときだけ reducer に伝える**：ドラッグ中に state を何度も更新すると、そのたびに localStorage への保存が走るため。Esc での取り消しも、プレビューを捨てるだけで済む。
- **マウスはカードのどこからでも、キーボードは「移動」ボタンから動かす**：カード内の「編集」「削除」ボタンでスペースキーを押してもドラッグが始まらないようにするため。マウスは 5px 動かすまでドラッグを始めず、ボタンのクリックを通す。編集中のカードはドラッグできない。
- **開始日・期限日は時刻なしの日付文字列（`"2026-10-20"`）で持ち、未設定は `null`**：日時で持つとタイムゾーンによって日付がずれるため。この形なら文字列のまま比べても日付の前後と一致する。
- **保存形式を version 2 に上げ、読み込み時に version 1 のデータを変換する**：フェーズ1で入れたバージョン番号を初めて使った。既存のタスクには開始日・期限日を `null` で足すので、ブラウザに残っているデータを失わない。
- **期限切れは列に関係なく赤く表示し、「期限切れ」の文字も添える**：アプリにはまだ「完了」を表す仕組みがないため、今はシンプルにする（完了の扱いはフェーズ3の絞り込みで改めて決める）。色だけに頼らず文字でも伝える。
- **開始日が期限日より後なら保存できないようにする**：フォームでエラーを出して止め、ありえない期間のデータを作らせない。
- **ラベルはワークスペース全体で共有し、名前の重複を許さない**：どのボードでも同じラベルを使え、フェーズ3の課題一覧でボードをまたいで絞り込むときも扱いやすい。重複はフォームでエラーを出し、reducer でも無視する（二重の守り）。
- **ラベルの色は任意の色コードではなく、決まった8色の名前で持つ**：実際の色は CSS 変数でライト／ダークモードごとに決め、背景と文字の組み合わせで常に読みやすさを保つ。データは色の名前だけなので、見た目の調整でデータを変えずに済む。
- **ラベルを削除したら、付いていたタスクから自動で外す**：存在しないラベルを指す ID を残さない。確認ダイアログで何件のタスクから外れるかを伝える。
- **ラベルは `features/label/` に分ける**：タスクとは別に管理画面（サイドバー）を持つ独立した機能のため。カードや編集フォームからは表示用の部品だけを使う。
